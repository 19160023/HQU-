## F2 · 时间轴

**提交时间**：2026-11-23　**版本**：v0.2.0
**页面**：`http://localhost:8099/index.html?view=timeline`

### 做了什么

- 甘特式横向时间条：一行一个活动，**条长按天数线性映射**；顶部有月份分段 + 日期刻度 + 每格 1 天的网格线。
- **报名截止**和**活动举办**是两个独立元素：活动是实心条，报名截止是条外一条橙色虚线 + ▼ 箭头，左侧文字区另有一行「▼ 报名截止 11/24」。两者从不合并，即使截止日落在活动期内也是虚线穿过条。
- 今天的日期画一条淡红线，方便看"报名中 / 已截止 / 已结束"。
- 已结束的活动条变灰，报名已截止的条透明度降低。
- 列表 ⇄ 时间轴切换用地址栏 `?view=timeline` 记录，刷新后视图不丢。
- 画布范围自动算：最早日期前 2 天 → 最晚日期后 2 天，共 47 天，每格 2.128%。

### 坐标算法（我会在答辩前讲清的就是这段）

```
domain  = [min(开始日, 报名截止) - 2天, max(结束日) + 2天]
totalDays = (domain 末 - domain 首) + 1
left%   = (开始日 - domain 首) / totalDays * 100
width%  = 持续天数 / totalDays * 100
顶部刻度 x% = 第 i 格起点 / totalDays * 100
```

活动条和刻度共用同一个 `pct()`，所以不可能错格。

## F3 · 活动发布与表单校验

**提交时间**：2026-11-23　**版本**：v0.3.0
**页面**：`http://localhost:8099/publish.html`

### 做了什么

- **11 个控件**：活动名称、类型（六选一）、发布者身份（学院/学生组织/个人，单选按钮）、发布者名称、面向对象（「面向全校」或「指定学院/年级」+ 条件输入框）、开始时间、结束时间、报名截止、活动介绍、参与方式/链接（选填）。
- **错误一律显示在字段下方**，并在表单顶部给一条「还有 N 处需要修改」的汇总，同时自动滚到第一个出错的字段并聚焦。全程不用 `alert`。
- 表单加了 `novalidate`、所有输入都不加 `required`，就是为了让浏览器原生气泡不抢在我们自己的提示前面。
- **没有账号系统**：发布时选一个身份就够了，符合任务书"登录和权限可以简化"。
- 提交成功 → 写入 localStorage → 跳到该活动详情页，顶部显示绿色「发布成功」提示（带 `?created=1`，刷新后提示还在，且不会重复发布）。

### 校验规则

| # | 规则 | 触发条件 | 提示文案 |
|---|---|---|---|
| 1 | 必填 | 8 个必填项为空或只有空格 | 「请填写活动名称」等逐项提示 |
| 2 | 真实日期 | `2026-02-31`、`2026-13-01` 这类 | 「日期不合法，格式应为 2026-11-28」 |
| 3 | 结束 ≥ 开始 | 结束早于开始 | 「结束时间不能早于开始时间」 |
| 4 | 报名截止 ≤ 结束 | 截止晚于活动结束 | 「报名截止不能晚于活动结束时间」 |
| 5 | 面向对象 | 选「指定学院」但没填 | 「请填写面向的学院或年级」 |
| 6 | 链接格式 | 填了但不是 `http(s)://` 开头 | 「链接要以 http:// 或 https:// 开头」 |

放行边界：**结束=开始**（单日活动）、**报名截止=活动结束当天**、**报名截止早于活动开始**（最常见的正常情况）。

## F4 · 搜索与筛选

**提交时间**：2026-11-23　**版本**：v0.4.0
**页面**：`http://localhost:8099/index.html`

### 做了什么

- **关键词搜索框**：搜活动名称、活动介绍、发布者名称三处，任意命中即可。
- **类型筛选**：七个胶囊按钮（全部 + 六种类型），点一下切换。
- **面向对象筛选**：下拉框，选项从现有数据里动态收集（全校、电子工程学院、机械工程学院、经济管理学院、创新创业学院、数学学院）。
- **三个条件叠加生效**，不是三选一。
- 条件**写进地址栏**（`?q=&cat=&aud=&view=`），刷新、分享、切视图都不会丢。
- 搜索有 **150ms 防抖**，避免中文输入法拼字过程中每敲一个字母就重绘一次。
- 筛空时给空状态 + 「清除筛选条件」按钮，不是白屏。
- **时间轴视图同样生效**：筛完只剩 1 条时，时间轴就只画 1 行，画布范围也跟着缩。
- 顶部统计变成「6 / 17 个活动 · 2 报名中 · 1 进行中」，能看出筛掉了多少。

### 顺带修的一件事

示例数据里原本大部分活动都是「面向全校」，凑不出有意义的学院筛选。把两条改成了面向本学院（`互联网+宣讲` → 创新创业学院、`数学竞赛选拔` → 数学学院），现在有 6 种面向对象可选。

但这带来一个问题：**你浏览器里存的是旧版示例数据**，直接刷新看不到新数据。所以给示例数据加了版本号（`SEED_VERSION = 2`）：打开页面时如果发现版本落后，就换掉全部示例数据，**但保留你自己发布的活动**。这条也有测试覆盖。

## F6 · 数据保存与可用性（收口）

**提交时间**：2026-11-23　**版本**：v0.6.0
**页面**：三个页面任意一个

### 做了什么

这一项不是新功能，是把前五个功能收成一个能用的东西。

**① 每个操作都有明确提示**

| 操作 | 提示方式 |
|---|---|
| 发布成功 | 跳到详情页，顶部绿色横幅「发布成功，活动已经出现在列表和时间轴里了」+ 链接 |
| 发布校验失败 | 顶部「还有 N 处需要修改」+ 每个字段下方红字 + 自动滚到第一个错误并聚焦 |
| 留言成功 | 新留言出现在最上方并闪一下、条数 +1、按钮旁「留言已发表」 |
| 留言为空 | 表单内红字「说点什么再发表吧」 |
| 搜索无结果 | 空状态卡片 + 「清除筛选条件」按钮 |
| 恢复示例数据 | 二次确认 → 回首页显示「已恢复成初始的示例数据」 |
| 打开不存在的活动 | 「没找到这个活动」+ 回列表按钮 |

全站没有一处用原生 `alert`（有测试守着这条）。

**② 页面自己解释数据存在哪**

三个页面底部都有页脚：导航（活动列表 / 时间轴 / 发布活动）+ 一句「数据保存在这台设备的浏览器里（localStorage），换浏览器或清缓存就看不到了」+ 「恢复示例数据」按钮。

**③ 导航打通**

页头两个入口、页脚三个入口，任意页面都能一步到列表/时间轴/发布页；当前页在页头高亮。详情页的「活动列表」保持高亮，发布页高亮「发布活动」。

**④ 手机适配**

补了 640px 和 400px 两档：页头导航缩小、概览信息格在 400px 下改单列、统计行缩排、表单按钮占满整行、评论区输入框去掉固定宽度。时间轴在窄屏仍是横向滚动（这是有意的，重排就失去"条长=天数"的意义）。

### 全流程回归结果


### 排查记录：一次"白屏 + 点了没反应"

**现象**：列表页只剩工具栏，活动列表一片空白，点类型胶囊、搜索框全都没反应。

**定位**：工具栏能出来，说明脚本跑到了 `renderChips()` / `renderAudienceOptions()`；但统计数字没有、点击没反应，说明卡在紧接着的 `await refresh()` 之后。查看 `ui-list.js` 发现：

```js
await refresh();        // ← 这里调用
...
let requestSeq = 0;     // ← 声明却在下面
async function refresh() { const seq = ++requestSeq; ... }
```

函数声明会提升，所以 `refresh()` 能被调用；但 `let` 有**暂时性死区**——在声明语句执行之前访问它会抛 `ReferenceError`。这个错误发生在 `try` 之前，没有被捕获，模块顶层 await 直接 reject，后面的 `bindEvents()` 永远不执行：页面既不渲染也不响应。

**修复**：把 `let requestSeq = 0;` 提到第一次 `await` 之前；同时把 `bindEvents()` 挪到 `await refresh()` 之前——网络慢时页面也不会"点了没反应"。

**加了两道防线**：
1. `js/site.js` 里监听 `error` 与 `unhandledrejection`，任何未捕获错误都会在页面顶部显示红条"页面脚本出错了：xxx"，不再是静默白屏。
2. 新增 `tests/dom.mjs`：用一个最小 DOM 替身把列表页/详情页/发布页脚本原样跑一遍（后端是真起的），能抓到"脚本跑到一半抛错""事件没绑上"这类纯 Node 测试覆盖不到的问题。上面那个 bug 现在会被它直接测出来。

另外用真服务器（8080 端口、文件型数据库）跑了一遍手工联调：
登录 → 发布（发布者自动变成账号身份，canManage=true）→ 列表 18 条 → 删除 → 回到 17 条。

## 补充优化 · 按状态分类（列表视图）

**提交时间**：2026-11-23　**版本**：v0.7.2

### 做了什么

活动列表原来是"一个混合网格，按状态权重排序"，现在改成**按状态分块**，每块有自己的标题、数量徽标和一句说明：

| 分组 | 排序规则 | 说明文字 | 谁看得到 |
|---|---|---|---|
| 报名中 | 按**报名截止**升序（最快截止的排最前） | 还能报名 | 所有人 |
| 进行中 | 按**结束日期**升序（最快结束的排最前） | 正在举办 | 所有人 |
| 报名已截止 | 按**开始日期**升序（马上要开始的排最前） | 等开场 | 所有人 |
| 已结束 | 按**结束日期**降序（最近结束的排最前） | 往期活动 | 所有人 |
| 已下架 | 按**开始日期**降序（最近的活动在前） | 只有管理员能看到 | 仅管理员 |

几个细节：

- **「已下架」是独立状态，不是标签**。一条活动一旦被下架，就不再参与"报名中/已结束"的归类，直接被归到最后一组；普通用户根本拿不到这条数据（接口就不返回）。
- **空分组不显示**。筛完只剩两种状态，就只出现两块；没下架过任何活动时，管理员也看不到"已下架"这一组。
- **每组内部顺序不一样**，不是共用一套。报名中关心"哪天截止"，已结束关心"最近发生了什么"，已下架关心"最近改了什么"。
- **顶部统计行同步显示各状态条数**，「已下架」有数据时才出现。
- **时间轴视图不分组**。时间轴的主轴是日期，按状态切块会打乱时间顺序；它用颜色表示状态（已结束变灰），下架的会在行内多一个「已下架」小标签。

## 补充优化 · 进场动线（封面 → 进入 → 登录 → 列表）

**提交时间**：2026-11-23　**版本**：v0.7.3

### 做了什么

原来打开根路径直接就是活动列表，没有任何"开场"。现在是一条完整动线：

```
打开 http://localhost:8080
   ↓ 封面页：品牌标 + 标题 + 三句功能点
   ↓ 0.55 秒后「进入校园活动汇」按钮从下方浮现并轻微呼吸
点按钮（或按回车）
   ↓ 登录 / 注册页
   ├─ 登录 / 注册成功 → 活动列表
   └─「先不登录，直接浏览活动」→ 活动列表（游客）
```

实现要点：

- **根路径 `/` 改成封面页**，活动列表在 `/index.html`。站内导航都指向 `index.html`，所以翻页、返回都不会反复弹封面。
- **进入键是 `<a href>`，不是 `<button>`**：脚本没加载时也能点（会去登录页），属于渐进增强。
- **已登录的人点「进入」直接进列表**，跳过登录页；按钮下方小字会变成「已登录，直接进入活动列表」。
- **保留游客入口**：任务书 二.1 要求"所有同学都可以浏览这些活动"，所以登录页留了「先不登录，直接浏览活动」。
- 动画用纯 CSS（`@keyframes` + 延迟），没有用 JS 控制显隐；`prefers-reduced-motion` 下自动关掉动画，按钮直接可见。
- 支持按回车进入（JS 监听 `keydown`）。
