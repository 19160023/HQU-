# 接口说明

基地址：`http://localhost:8080/api`
格式：请求和响应都是 JSON；失败时返回 `{ "error": "给人看的一句话", "errors": { "字段": "提示" } }`（`errors` 只在表单类校验失败时出现）。
认证：登录成功后服务端下发 `sid` Cookie（HttpOnly，7 天有效），之后所有请求自动带上；前端不需要、也拿不到 token。

---

## 一、认证

### `POST /api/auth/register` 注册

请求：

```json
{
  "account": "student02",
  "password": "secret123",
  "displayName": "王小明",
  "publisherType": "personal",
  "publisherName": "王小明（软件学院）"
}
```

| 字段 | 规则 |
|---|---|
| account | 4–20 位字母、数字、下划线，唯一 |
| password | 至少 6 位 |
| displayName | 1–20 字 |
| publisherType | `college` / `org` / `personal` |
| publisherName | ≤ 30 字，留空用 displayName |

响应 `201`：`{ "user": { id, account, displayName, role, publisherType, publisherName } }` + `Set-Cookie: sid=...`
错误：`409` 登录名已被占用；`422` 字段不合法。

### `POST /api/auth/login` 登录

请求 `{ "account": "...", "password": "..." }` → `200 { user }` + Cookie；失败 `401 { "error": "账号或密码不对" }`（不区分是账号不存在还是密码错）。

### `POST /api/auth/logout` 退出

删除服务端会话并下发过期 Cookie → `200 { "ok": true }`

### `GET /api/auth/me` 当前用户

已登录 → `200 { "user": {...} }`；未登录 → `200 { "user": null }`

## 二、活动

### `GET /api/activities` 列表（支持搜索与筛选）

查询参数（都可省略，可叠加）：

| 参数 | 说明 |
|---|---|
| `q` | 关键词，匹配标题 / 介绍 / 发布者名称（SQL `LIKE`，`%` 和 `_` 已转义） |
| `category` | 活动类型精确匹配 |
| `audience` | 面向对象精确匹配 |

响应 `200`：`{ "items": [activity...], "total": 3 }`

排序：`start_date ASC, title ASC`。登录管理员能看到已下架的活动（带 `hidden: true`），其他人看不到。

### `GET /api/activities/:id` 详情

`200 { "activity": {...} }`；不存在或已下架（非管理员）→ `404`。

### `POST /api/activities` 发布（需登录）

请求体与发布表单一致：`title, category, audienceScope, audienceDetail, startDate, endDate, signupDeadline, description, link`。

> **`publisherType` / `publisherName` 不用传，传了也会被忽略**——服务端一律取登录账号的身份，防止冒充学院或学生组织。

响应 `201 { "activity": {...} }`；`401` 未登录；`422` 校验失败（`errors` 里是每个字段的原因）。

### `DELETE /api/activities/:id` 删除（需登录，作者或管理员）

`200 { "ok": true }`；`401` 未登录；`403` 不是作者也不是管理员；`404` 不存在。

### `POST /api/activities/:id/visibility` 下架 / 恢复（仅管理员）

请求 `{ "hidden": true }` → `200 { "activity": {...} }`；非管理员 `403`。

## 三、留言

### `GET /api/activities/:id/comments`

`200 { "items": [{ id, activityId, nickname, content, createdAt }], "total": 3 }`，按 `created_at DESC`。

### `POST /api/activities/:id/comments` 发表留言

请求 `{ "nickname": "可选", "content": "必填" }`。**不要求登录**（游客也能补报名经验），登录用户会顺带记录 `created_by`。

响应 `201 { "comment": {...} }`；`422` 内容为空或超 500 字；`404` 活动不存在或已下架。

---

## 四、其他

### `GET /api/meta` 筛选项

`200 { "categories": [...], "publisherTypes": [...], "audiences": [...] }`，`audiences` 从数据库里去重取，「全校」排最前。

### `POST /api/admin/reseed` 恢复示例数据（仅管理员）

清空活动与留言后重新灌入 17 条示例 + 6 条留言，**保留用户账号**。响应 `200 { "ok": true, "activities": 17 }`。

## 五、用 curl 手工试一下

```bash
# 登录并保存 Cookie
curl -i -c cookie.txt -H "Content-Type: application/json" \
     -d '{"account":"student01","password":"student2026"}' \
     http://localhost:8080/api/auth/login

# 带 Cookie 发布
curl -b cookie.txt -H "Content-Type: application/json" \
     -d '{"title":"测试活动","category":"讲座报告","audienceScope":"all",
          "startDate":"2026-12-20","endDate":"2026-12-20",
          "signupDeadline":"2026-12-18","description":"来自 curl"}' \
     http://localhost:8080/api/activities

# 搜索
curl "http://localhost:8080/api/activities?q=摄影"
```

## 六、状态码约定

| 码 | 含义 |
|---|---|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 请求体不是合法 JSON |
| 401 | 没登录 / 会话过期 |
| 403 | 登录了但没权限 |
| 404 | 不存在，或已下架（对当前用户不可见） |
| 409 | 冲突（登录名被占用） |
| 413 | 请求体太大 |
| 422 | 表单校验没通过（带 `errors`） |
| 500 | 服务端异常 |
